# 02. CUDA란 무엇인가

> **질문 1**: CUDA란?
> **질문 2**: 엔비디아 GPU를 갈궈서 계산하는 데 특화된 함수를 모아놓은 라이브러리라고 이해하면 되나?

## 한 줄 답

**CUDA는 "GPU라는 별도의 컴퓨터를 프로그래밍하기 위한 개발 환경 일체"** 이고,
최적화된 계산 라이브러리는 그 안의 **한 층**일 뿐이다.

---

## 1. 오해 교정

| 처음 이해한 것 | 평가 |
|---|---|
| NVIDIA GPU 전용 | ✅ 정확 |
| 계산에 특화 | ✅ 정확 |
| **"함수를 모아놓은 라이브러리"** | ⚠️ **일부만 맞음** — 라이브러리는 CUDA의 한 층이다 |

비유하자면, "numpy 같은 패키지"로 이해한 것인데
실제로는 **"파이썬이라는 언어 + 인터프리터 + 표준 라이브러리 전부"** 에 가깝다.

## 2. CUDA의 4가지 구성 요소

| 구성 | 역할 | venv에 설치된 것 |
|---|---|---|
| 언어 확장 | C++에 "이 함수는 GPU에서 돌려라" 문법 추가 | (헤더의 `__global__` 등) |
| 컴파일러 | GPU 기계어(PTX)로 번역 | `nvidia-cuda-nvrtc`, `torch/bin/ptxas` |
| 런타임 | GPU 메모리 할당, 커널 실행, 데이터 전송 | `nvidia-cuda-runtime` |
| **수학 라이브러리** | 행렬곱·FFT·난수를 극한 최적화해 미리 구현 | `nvidia-cublas`, `nvidia-cudnn` |

**실무 성능을 만드는 건 맨 아랫줄이다.** 아무도 GPU 행렬곱을 직접 짜지 않고,
NVIDIA가 수년간 튜닝한 cuBLAS/cuDNN을 호출할 뿐이다. PyTorch가 하는 일도 결국 그거다.

## 3. 증거 A — CUDA는 "언어"이기도 하다

```bash
grep -rhoE "__(global|device|host|shared|constant)__" venv/.../nvidia/*/include/*.h | sort | uniq -c
```

| 키워드 | 등장 | 의미 |
|---|---|---|
| `__host__` | 604 | 이 함수는 **CPU**에서 실행 |
| `__device__` | 434 | 이 함수는 **GPU**에서 실행 |
| `__global__` | 13 | CPU가 호출하고 **GPU가 실행** (진입점) |
| `__constant__` | 12 | GPU 상수 메모리에 배치 |

**이건 C++ 문법이 아니다.** 표준 C++ 컴파일러에 넣으면 에러가 난다.
NVIDIA가 C++을 확장해 만든 새 문법이고 `nvcc` 전용 컴파일러로만 빌드된다.

즉 CUDA는 함수를 *호출하는* 데 그치지 않고 **GPU에서 돌 코드를 직접 작성하는 언어**다.

## 4. 증거 B — GPU는 "별도의 컴퓨터"다

이게 가장 중요한 개념이다. CUDA 런타임 API 655개 중:

```
cudaMalloc               <- GPU 메모리 할당 (CPU의 malloc과 별개!)
cudaFree                 <- GPU 메모리 해제
cudaMemcpyHostToDevice   <- CPU 메모리 -> GPU 메모리 복사
cudaMemcpyDeviceToHost   <- GPU 메모리 -> CPU 메모리 복사
cudaLaunchKernel         <- GPU에서 코드 실행 시작
cudaDeviceSynchronize    <- GPU 작업이 끝날 때까지 CPU 대기
```

**`malloc`과 별개로 `cudaMalloc`이 있다는 것** = GPU는 자기 전용 메모리(VRAM)를 가진
독립된 컴퓨터라는 뜻이다. 데이터를 명시적으로 실어 보내고 결과를 받아와야 한다.

`HostToDevice` / `DeviceToHost`처럼 **방향이 이름에 박혀 있는 것**이 결정적 증거다.
같은 컴퓨터 안이면 이런 구분 자체가 필요 없다.

## 5. 왜 GPU가 딥러닝에 빠른가

| | 이 서버 CPU | 일반적인 GPU |
|---|---|---|
| 코어 수 | **2개** | **수천 개** |
| 코어 하나의 성능 | 강력, 복잡한 분기 처리 | 약함, 단순 계산만 |

500×500 행렬곱은 곱셈-덧셈 1.25억 회인데 **각 계산이 완전히 독립적**이다.
이런 작업엔 "똑똑한 일꾼 2명"보다 **"단순한 일꾼 5,000명"** 이 압도적으로 유리하다.
신경망 연산 대부분이 이 모양이라 GPU가 10~100배 빠르다.

반대로 `if` 분기가 많고 순서대로 처리해야 하는 일반 프로그램은 GPU에서 오히려 느리다.

## 6. 전체 계층

```
cuBLAS, cuDNN, cuFFT      <- "함수 모음(라이브러리)". 처음 이해했던 부분
CUDA 런타임 API           <- 메모리 할당, 커널 실행 (655개 함수)
CUDA 언어 확장 + nvcc     <- __global__ 문법, 전용 컴파일러
NVIDIA 드라이버
GPU 하드웨어
```

**이 사슬은 맨 아래부터 하나라도 없으면 끊긴다.**

## 7. 이 서버의 실제 상황

`torch 2.11.0+cu130` 의 **`+cu130` = "CUDA 13.0용으로 빌드됨"**.
그런데 `/dev/nvidia*`가 아예 없다 → 드라이버도 하드웨어도 없음 → `cuda.is_available() == False`.

| 항목 | 용량 |
|---|---|
| `nvidia/` 패키지 19개 | 2.7 GB |
| `triton` (GPU 커널 컴파일러) | 641 MB |
| torch 내부 CUDA 라이브러리 | 487 MB |
| **합계 (전부 미사용)** | **약 3.8 GB** |

venv 5.7 GB의 대부분이 이것이다.

### 지울 필요는 없다

- **RAM에는 영향이 없다.** PyTorch는 CUDA 라이브러리를 GPU가 있을 때만 지연 로딩한다.
  지금은 메모리에 올라오지도 않는다.
- 디스크만 차지하는데 여유가 22 GB 있다.
- CPU 전용으로 재설치하다 **잘 돌아가는 환경을 깨뜨릴 위험**이 더 크다.

## 8. NVIDIA가 아니면?

CUDA는 **NVIDIA 전용**이다. 이게 NVIDIA가 AI 시장을 장악한 핵심 이유다.

| 백엔드 | 대상 | PyTorch 지원 |
|---|---|---|
| CUDA | NVIDIA | 완숙 (사실상 표준) |
| ROCm | AMD | 되지만 손이 감 |
| MPS | Apple Silicon | 꽤 쓸 만함 |
| **XPU** | **Intel GPU** | 실험적 |

91.44의 Core Ultra 7 265K 내장 그래픽은 XPU 계열이다.
이론상 `intel-extension-for-pytorch`로 쓸 수 있지만, 별도 드라이버가 필요하고
내장 그래픽은 전용 VRAM 없이 시스템 RAM을 나눠 쓴다.
**20코어 CPU로 그냥 돌리는 것보다 나을 거라 기대하기 어렵다** → 계획대로 CPU 학습.

---

## 이 프로젝트와의 연결

- 이 프로젝트는 처음부터 **CPU에서 돌아가도록** 설계했다. CUDA는 한 번도 쓰지 않는다.
- 그래도 4절(GPU는 별도 메모리)은 반드시 알아야 한다.
  나중에 GPU 장비가 생겼을 때 OOM 앞에서 무엇을 줄일지 판단하는 근거가 된다.
